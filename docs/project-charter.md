# 拾光清理：执行章程与里程碑

用户已要求按会话中的 Android 优先、LLM + Jev + Ontology 方案实现。该指令作为开发范围授权；不重复申请同一方案的批准。所有代码位于新建的 `media-cleaner` 项目，不修改其他项目，不对用户现有媒体执行清理，不发布到应用商店。

## 当前交付范围

用户追加「需要扩展支持 web 应用」，授权在 `web/` 增加浏览器版本，保留 Android 实现。Web 沿用 LLM + Jev + Ontology 责任边界，以 File System Access / Worker / IndexedDB 落地本地处理；无目录写入能力时只读分析与导出。无需媒体上传后端，不发布外部站点。Web 门禁包括核心安全测试、构建、浏览器交互及系统目录授权验收；后两项因环境限制仍待完成，详见 `web-verification.md`。

Android 8.0+ 原生应用：系统目录授权、本地遍历、完整哈希去重、相似照片人工筛选、文件保护、结构化计划、版本绑定确认、永久删除、执行校验与日志、LLM/Jev 网关适配。

主体技术：Kotlin、Compose、SQLite；纯 JVM 核心模块保存类型模型、分组、计划和规则执行逻辑。真实 Jev 接入需官方 API/SDK 或用户网关，尚未提供；本地模式明确标记为规则推理。扫描只针对 Android 本地外部存储 DocumentsProvider，不支持云盘、其他应用私有目录。

## 边界与假设

- 用户通过操作系统授权目录，并通过具体计划批准删除；开发期间只可操作专门生成的测试样本。
- 默认不调用网络模型。远程调用需要用户设置 HTTPS 网关并开启发送必要结构化信息。
- 不实现同盘回收站；删除是永久删除，确认弹窗明确说明。
- 第一版交付清理闭环，压缩按已设计的第三阶段后续实现；不以界面占位冒充已实现。
- 前台分析支持暂停和缓存复用，未实现调度式后台扫描。
- 模型 SDK、真机行为与性能存在外部依赖，必须明确区分源码实现、编译验证和运行验证。

## 里程碑与质量门禁

1. 目录到计划：真实 SAF 访问、SHA-256、直接锚点相似比较、结构化存储和预览。门禁为类型编译和文件边界测试。
2. 确认到执行：计划摘要绑定、最新快照校验、保留副本依赖、持久日志及中断恢复。门禁为误删路径单元测试与合成文件设备验收。
3. 模型适配与交接：受限策略输出、匿名特征决策、严格响应校验、无模型可用时人工复核。门禁为接口契约检查、真实供应商联调（待接入资料）、安装包与设备测试。

## 验收原则

不得以测试通过宣称算法能够理解个人照片价值。相似项始终由用户选择；哈希一致只说明字节相同。自动化验证必须覆盖：权限丢失、文件变更、保留项缺失、非法模型输出、重复执行、计划篡改、执行中断及容量归属。未完成手机端构建或实测时，不宣称生产可用。
